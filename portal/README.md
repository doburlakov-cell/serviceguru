# ServiceGuru Portal — единый вход

Сотрудник входит в портал одним логином и паролем. Клик по плитке проекта — и он уже внутри, без второго пароля.

## Как это работает
1. Портал проверяет логин/пароль и ведёт сессию.
2. Клик по плитке → портал выдаёт токен (RS256, живёт 60 секунд, выписан только для этого проекта) и переадресует на `<проект>/sso/callback?token=…`.
3. Проект проверяет подпись публичным ключом портала, ставит свою сессию (по умолчанию 4 часа) и открывает страницу.
4. Открыли проект напрямую без входа — проект сам отправит в портал и вернёт обратно.
5. Отключили сотрудника в портале — новых входов нет, а текущие сессии в проектах истекают в пределах `SSO_SESSION_HOURS`.

Домен не нужен: всё работает через токены между разными адресами (onrender.com, vercel.app и т. д.).

## Запуск на Render
В `render.yaml` уже есть сервис `serviceguru-portal` (`rootDir: portal`). Переменные:
- `SECRET_KEY` — генерируется само, потом не менять;
- `PORTAL_URL` — публичный адрес портала, например `https://serviceguru-portal.onrender.com`;
- `DATABASE_URL` — Postgres (например, тот же Neon). **Без него данные хранятся в SQLite и пропадают при перезапуске на Render**;
- `ADMIN_LOGIN`, `ADMIN_PASSWORD` — создают первого администратора при пустой базе (после первого входа пароль смените в «Аккаунте»).

## Подключение проекта
1. В портале: «Подключения» → «Добавить проект». `id` (например `contracts`), адрес проекта, тип «Единый вход».
2. В проекте скопируйте `sso_client.py` и добавьте после создания `app`:
   ```python
   from sso_client import install_sso
   install_sso(app, public_paths=("/api/health",))   # пути без входа: проверки здоровья, cron, вебхуки
   ```
   Нужны пакеты `PyJWT` и `cryptography`.
3. Переменные проекта: `PORTAL_URL`, `SSO_APP_ID` (= `id` из портала), `SESSION_SECRET` (случайная строка). Пока они не заданы, проект работает по-старому — можно раскатывать без риска.
4. В «Сотрудниках» выдайте людям доступ к проекту.

Уже подключены (по этой схеме): генератор договоров (`main.py`, `SSO_APP_ID=contracts`) и рассылка Telegram (`broadcast_app`, `SSO_APP_ID=broadcast`; `/api/tick` остаётся под `CRON_SECRET`). Проекты не на FastAPI (Node и т. п.) подключаются так же: проверить JWT RS256 публичным ключом с `/.well-known/portal-public-key.pem`, проверить `aud` = id проекта и `iss` = адрес портала.

## Сторонние сервисы (amoCRM, Wazzup, Мегафон)
Свой вход в них не встроить. Добавьте их типом «Только ссылка» — плитка в портале. Настоящий единый вход возможен, если сервис поддерживает вход через Google/Яндекс/SAML — это зависит от тарифа.

## Безопасность
Пароли хранятся как scrypt-хэш; CSRF-токены в формах; блокировка входа на 5 минут после 5 неверных попыток; администратор не может отключить себя; токен действует 60 секунд и привязан к проекту; адреса переадресации берутся только из списка подключённых проектов.
